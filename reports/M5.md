## Built

- `/portfolio`: close-date quick entry for account net liquidation value and whole SOXL shares, numeric keypads, add/edit/remove SOXL put rows, and snapshot history with edit links. Net put credit is entered per option share after entry fees. Existing-date saves replace only that snapshot.
- Entered NAV, entered-history drawdown/kill status, core exposure, put notional and model gap exposure, each with formula workings. Model valuations use the shared engine and matching-date stored bars. A notice distinguishes unverified stored market history from actionable runs. Missing-date model values remain unconfirmed.
- Consistency warnings compare the prior consecutive NYSE snapshot and its valid final share estimate. They flag share differences, new/modified/removed puts, expired positions, nonconsecutive snapshots and unconfirmed prior advice. Removing a put never fabricates a fill or realized P&L.
- Execution journal with server-captured recommendation/run ID, actual action text and note. It is append-only. A matching valid final is required to capture confirmed advice; otherwise the recommendation explicitly says unconfirmed. A snapshot must exist before journaling that date. User text renders as React text, not HTML.
- Authenticated `GET /api/portfolio` and `PUT /api/portfolio`, strict Zod request/response/file validation, 64KB body limit, same-origin JSON writes, private atomic file replacement, exclusive writer lock and combined entries/journal revision. Contention and stale tabs receive 409 rather than overwriting newer data. No authentication bypass was added.
- Run account-basis tracking: the complete snapshot history through each run date is recorded in `working.account.snapshot`. Editing current positions or earlier NAV/entry-week history blocks old actions in Today and the run API until a new run is generated. Future snapshots do not invalidate historical runs. Journals and consistency checks apply the same basis check. Old runs without a recorded basis require a rerun.
- Responsive forms and stacked phone tables, 44px buttons and visible keyboard focus; Build/health now report M5 with `strategyReady: false`.

## Choices, deviations and limitations

- Used existing React form state, Zod, native inputs/tables and theme CSS. No new dependencies were required. All market and exposure calculations remain on the server and reuse the engine.
- Authenticated APIs and form gating are implemented, but full password/TOTP login remains M8 as scheduled. Tests use a test-only environment secret and signed sessions. Until M8, this milestone remains loopback-only and normal user saving cannot be demonstrated via a login screen. This is an explicit acceptance qualification, not a relaxed authentication rule.
- Entered-history drawdown cannot recover peaks that were never entered and is not adjusted for cash transfers. One snapshot starts at zero drawdown. Positions are never inferred from backtest equity. Earlier snapshot corrections require rerunning dependent analyses; later snapshots are independent records.
- A process crash can leave the portfolio write lock. Further writes fail closed; an operator must confirm no writer is active before removing it. The app remains a single Node process on persistent local disk.
- Journal actual actions are free text and notes, as specified. Structured fill accounting and realized P&L are not inferred from snapshot differences.
- No broker, orders, alerts, public deployment, strategy-constant changes or edits to Backtest/, Strategy/ or the plan.
