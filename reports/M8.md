# M8 — Authentication and deployment packaging

Date: 18 November 2026

Status: **Implementation and local verification complete; Docker/VPS acceptance remains open.** No public deployment or actual owner enrollment was performed.

## Built

- Password + authenticator login with bcrypt cost 12 setup, otplib six-digit TOTP, adjacent-step clock tolerance, and persisted rejection of reused codes.
- Twelve-hour signed owner sessions; `__Host-` cookie is Secure, HttpOnly, SameSite=Strict, path `/`, with no Domain. Logout clears it; rotating SESSION_SECRET invalidates all signed sessions.
- Next 16 Proxy protection for pages, RSC requests and APIs, plus checks before private page reads and independent API guards. Login, its POST endpoint, health and required static framework/manifest/icon resources are public.
- Fixed configured `APP_ORIGIN` for CSRF protection through a TLS reverse proxy; forwarded host/protocol/IP headers do not establish trust.
- Strict Zod login/config/result/state validation, 2KB streamed request bound, generic authentication errors and a global five-attempt/15-minute limit. Rate state and TOTP replay state persist atomically on disk; an exclusive lock serializes verification. Missing credentials or corrupt auth state fail closed.
- `pnpm auth:setup`: interactive hidden password/confirmation, generated private QR, authenticator enrollment check, exclusive `.env.local` creation, and 0600 file permissions. No actual owner credentials were generated during this milestone.
- Responsive green login and sign-out control. Dashboard routes moved into a protected route group, without changing their public URLs or strategy calculations.
- Multi-stage Node 24 Dockerfile, unprivileged runtime, health check, loopback default port, named persistent data volume, and optional Caddy HTTPS profile. Runtime credentials/data are excluded from the build context. Build packaging removes runtime data/environment files that Next can otherwise copy through instrumentation tracing or environment handling.
- README setup, production, TLS, backup/recovery, session rotation and single-process operating instructions. Development and production still seed/register the scheduler automatically.

## Review findings addressed

- Earlier dashboard tests expected unsigned read access and an unauthorized Run now response. They now run with explicit regression sessions; separate auth tests exercise real login. The Run now UI test uses a deterministic busy response and makes no live market request.
- A manually created mobile browser context lacked the regression session; it now explicitly receives one.
- Setup entered raw terminal mode after displaying its prompt, creating a possible input-echo race. Raw mode and its listener now precede the prompt.
- Next instrumentation tracing included runtime data despite route tracing exclusions. The final build packaging step removes data, environment, enrollment, test and report files from standalone output; Docker independently excludes these from its context.

## Deviations and remaining acceptance

- **Docker is unavailable on this machine (`docker` executable absent).** Image build, `docker compose up`, container-user permissions and volume persistence through container recreation were not run. Compose YAML parsing and local standalone checks do not establish these results.
- No VPS host/domain or real enrolled owner credentials are configured. Public HTTPS, real phone/mobile-data access and three unattended US trading days remain unverified. They require deployment resources and elapsed sessions.
- The brief requires setup for an actual owner; the supplied command is ready, but personal enrollment must be completed locally in the owner's terminal. No placeholder/default owner password is installed.
- The rate limit is global for one owner. This avoids trusting spoofable IP headers, at the cost of a possible 15-minute denial of login under deliberate abuse. Stateless logout clears the browser cookie; a copied session requires secret rotation or expiry to revoke. Both tradeoffs are documented.
- Existing stack substitutions remain documented. No new strategy constants, market-data policies, broker, order placement or alerts were introduced.
